# 6.416 原生可见窗口回调测量

日期：2026-10-20。证据目录：`logs/animation-6.416-live-final/`。本报告只读取已完成的 8 个正式 JSON、4 个独立诊断 JSON 和 `summary.json`，未重新测量、未修改生产或测量工具。

四格稳定阶段的 Qt paint 回调 P95 均下降约 2.10%–12.94%，P99 和最大值也均下降；仍有中位数、调度和冷阶段回归。**这不能验收为稳定 60 Hz，也不能称为物理屏幕 FPS 提升。** 实际呈现与输入延迟需要 DWM／物理测量；本报告保留这些限制。

## 测量范围与可比性

本组实际显示 Windows Qt 窗口，由真实事件循环触发 timer／paint 回调，采样期间不抓图、不导出 PNG。正式没有 profiler 或像素诊断 wrapper；paint 入口／出口与 tick 本身的计时仍有观察开销。两者独立、存在嵌套及事件循环调度，不可把分位数相加为“总帧时间”。`paint_callback_interval_ms` 是相邻 paint 回调的入口间隔，不是 compositor 帧间隔。

配置为逻辑 960×540，`long-song` 和 `unit-slow`，DPR 1／2。每进程 cold 2 秒＋stable 约 6 秒，收尾受事件循环调度影响，8 份正式的实际 observed_seconds 为 8.133–8.172 秒，4 份诊断为 8.138–8.181 秒。阶段采用相同时间窗，回调数量不同；不能将第 n 个 old 回调与第 n 个 new 回调作逐帧配对，也不能只比较绝对超预算数而不看样本数。JSON 只保留阶段分布汇总，不能从这些文件重建完整逐回调时间线。

所有正式与诊断 JSON 的 `application_source_unchanged` 均为 true，且 before／after 应用 SHA256 字典一致；同格 current 与诊断源码也一致。`summary.json` 的 8 组 phase 与 resources 与正式文件逐项相等。测量没有账号、网络、设置写入和实际音频；媒体位置为 fixture 驱动，不能替代后台真实播放体验。新源在 show 前等待生产共享歌词计划；旧源仍在 accessor 中同步处理，故新首 paint 减少不能单独称为端到端启动变快。

DPR 1 可用逻辑屏幕为 2560×1416；DPR 2 为 1280×708。四格及其诊断均记录窗口与可用屏幕交集 960×540、`wholly_inside_available_geometry=true`，没有发生本组窗口超出工作区。DPR 2 对应 1920×1080 物理像素，却不是逻辑 1920×1080 窗口；不能将本组结论外推到该更大逻辑窗口。`visible_at_finish=true` 仅证明结束时可见，不证明全程无遮挡。记录的 170.001 Hz 是显示器刷新率，不是程序达成的帧率。

## 独立像素流水线诊断

## 验收边界

本组证明了真实可见 Qt 窗口中的回调成本及部分尾部改善，同时保留冷阶段、稳定中位数、tick 及间隔占比的回归。它没有证明稳定 60 Hz、170 Hz、物理输入响应或材质交接已被屏幕显示，也没有涵盖真实音频、联网取词、HomePod、长时多窗口资源及所有页面过渡。1920×1080 逻辑大窗口的 live 对照没有出现在本组，应与离屏矩阵和独立生命周期报告分别阅读；不能互相替代。

本报告未改变视觉、交互或布局，也未对未测项目作通过结论。后续应继续定位 GUI 绘制及 pending 材质延迟；本轮不因后台化或较低 P95 就把全部动画性能目标标记为已完成。
