## Run

Start the app from `local/main.py`, or double-click `launch.bat`.

If dependencies are missing, run `setup-env.bat` once, then launch again. Runtime logs are written under `logs/`, which is ignored and can be deleted safely between runs.

The combined directory has its own Python environment and native HomePod helper under `build/native-airplay/`. Run its own `launch.bat`; the two original part directories are preserved. GluSpot's single-instance lock and user settings retain the normal product namespace, so exit an already running GluSpot before launching another source copy. Rebuilding the helper requires the toolchain documented in [native helper instructions](native/airplay_sender/README.md).

## Windows Test Build

GluSpot 6.411 uses a PyInstaller `onedir` package for local testing. This gives testers a normal executable while keeping Qt plugins, fonts, icons, data files, and local lyrics easy to inspect.

Build from the project root:

```powershell
.\build-exe.bat
```

Expected output:

```text
release\GluSpot-6.411\GluSpot.exe
```

The package is an unsigned internal test build. It is not an installer, does not include Steamworks ownership validation, and should not be treated as a public release artifact.

`GluSpot-6.411` is a complete `onedir` application. Keep `GluSpot.exe` beside its `_internal` directory; copying the executable alone is unsupported. The Windows package installs an early runtime hook that registers the bundled PySide6 and Shiboken DLL directories before `QtCore` is imported. The build also excludes build-host ICU DLLs: PySide6's Qt6Core needs the unversioned Windows ICU exports, while a versioned Poppler ICU discovered on `PATH` can shadow them and cause a Windows "entry point not found" error.

Known Windows test-build caveats:

- PyInstaller reports optional missing modules from Unix-only Python paths, NumPy/Pillow optional helpers, and setuptools internals; these are expected in a Windows GUI package unless a runtime feature proves otherwise.
- PyInstaller also reports missing `UIAutomationClient_VC140_X64.dll` / `UIAutomationClient_VC140_X86.dll` from the `uiautomation` dependency. The build still completes, but WeChat/QQ/DingTalk detail-detection paths should be checked on a real desktop.

## Startup

User-selectable startup is implemented in `local/startup.py` and exposed in the basic settings page.

Available modes:

- `none`: remove both supported startup hooks.
- `registry` / Windows startup item: use the current user's `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` entry.
- `task`: create a current-user scheduled task on logon. This is the recommended mode for GluSpot because it is an interactive tray/floating-window app.

Windows Service startup is intentionally not implemented. Services are not a good fit for this app because the island needs to interact with the signed-in user's desktop session.

## Current Product Direction

GluSpot is a Windows music island with plugin reminders, message notifications, and optional taskbar fusion.

The music surface should feel like a compact live object: album art, playback controls, lyrics, and album-color ambience remain readable in compact, expanded, Finder, Free, and Tasker placement modes.

The lyric target is Apple-like live lyric motion, not a visible progress bar. Actual unit timestamps drive the reading front when a source supplies them. Reading classification is song-wide: if any surviving row has genuine unit timing, both `金标读字` and `低感知方案` read the entire song, estimating missing unit timing from that row's original interval rather than switching paint modes mid-song. If no row has genuine timing, gold mode estimates reading and low-perception mode switches whole lines while retaining the visual-line spring. One timestamp covering multiple spoken words or CJK graphemes counts as row timing, even when the file uses an enhanced-LRC word marker. Plain lyrics with synthetic row times appear one row at a time in either mode. The strategy is shared by full-screen, windowed, and island music views. In gold mode, the OBO indicator appears as a white β on a dark circle beside the full-screen/windowed top-right mode control; genuine unit timing turns its ink and ring gold. Low-perception mode hides the badge. It follows the control's idle hide animation; the island has no badge.

## Settings Surface

The full-screen and windowed music pages share four compact circular controls: audio output, translation, the gold reading strategy's β badge, and the existing window/island destination. The output button uses a pale face with the confirmed device glyph; groups show one or two representative glyphs and their total playback count. Opening its chooser tints the glyph blue. No confirmed route retains the original output link. The chooser places selected or connecting targets first, preserving order within both buckets and postponing movement during volume dragging. Translation follows the existing dual-line setting and island view; enabled uses a pale face with a transparent 文/A cutout. The β badge is white until a surviving row has genuine unit timing, then gains gold ink and a gold ring; low-perception mode hides it. Their dimensions, gaps, idle-hide motion, hit targets, and snapshot transition behavior remain shared.

The full-screen lyrics page includes a Cantonese secondary-content card: phonetics first (Jyutping, default) or translation first, falling back to the available alternative. Source-provided phonetics are preferred; missing phonetics can be generated once using ToJyutping 3.2.0, with bounded per-text caching outside paint. Identification requires language metadata, supplied Jyutping, or distinctive Cantonese vocabulary. Standard written Chinese without reliable language evidence is not guessed from the artist. Both supplied secondary candidates, explicit language evidence and original unit times survive generated-cache persistence and source enrichment, including while translation is disabled; priority changes do not require a new online lookup. Untimed labeled companions stay within their original paragraph and never become separate synthetic lyric rows. The packaged dependency includes its dictionary and BSD-2-Clause license metadata.

The settings window is organized into:

- Basic settings: theme mode, startup mode, placement, Tasker/MyDockFinder controls, empty-island behavior, font and animation options.
- Media control: player mode, app profiles, BetterNCM path, lyric style, album island, lyric offsets, and ambience controls.
- Full-screen lyrics: `金标读字` / `低感知方案` reading strategy shared by all music views, the large music page's four-level reading lift (half-height default), continuous color-gradient width, sparse-highlight threshold, intro cleanup, and bilingual display. The remaining page controls also apply to the windowed music page; island lyric-style controls remain in Media control. The OBO (one by one) indicator is drawn as β beside the top-right mode control in gold mode, uses gold ink and a ring when any surviving row has genuine unit timing, and hides with that control.
- Plugin settings: TIME controls, weather settings, fullscreen plugin alert style, and agenda JSON/ICS controls.
- Notification settings: barrage and message notification controls.
- About: diagnostics, local project location, and music cache management. “清理封面并重试” discards downloaded covers, memory results and failure records; “清理在线歌词” discards generated online lyrics and restarts lookup. Both preserve manual lyrics, settings, offsets, playback position and audio-device state. Cleanup runs in the background and reports removed files, bytes and any failures.

Settings UI style lives mainly in `local/settings_window.py` and `local/mac_style.py`; small shared controls live in `local/no_wheel_widgets.py` and `local/ui_theme.py`.

## Placement Modes

- `Free`: normal floating island.
- `Finder`: used only when MyDockFinder is detected or explicitly available. Finder material may frame the island, but the island shell stays its own opaque V2 rendering path.
- `Tasker`: Windows taskbar fusion. The island follows the taskbar, including taskbar auto-hide. Fullscreen detection must not make Tasker disappear.
- `Stick`: internal auto-hide-taskbar placement. When Windows taskbar auto-hide is enabled, dragging the island to the bottom edge pins the free-style island just above the taskbar instead of entering Tasker.

MyDockFinder and Tasker are mutually exclusive:

- MyDockFinder running: allowed modes are `Free` and `Finder`.
- MyDockFinder not running: allowed modes are `Free` and `Tasker`; `Stick` can be reached only from the auto-hide-taskbar bottom-edge drag gesture.
- MyDockFinder detection has priority over taskbar auto-hide recognition, because Finder-style shells can hide the Windows taskbar themselves.

## Tasker Rules

- Tasker position is draggable across the taskbar range, including both bottom corners.
- Tasker should not snap to center by default.
- The left width handle is outside the island, appears on hover, and should hide after a short delay.
- Tasker compact layout can shrink down to album-cover mode when the taskbar is crowded.
- Tasker material and expanded outer frame should sample the taskbar style, not a generic wallpaper crop.
- Tasker mode keeps island visibility separate from fullscreen, plugin alerts, and barrage.
- With taskbar auto-hide disabled, dragging the island to the taskbar enters `Tasker`, and dragging Tasker out returns to `Free`.
- With taskbar auto-hide enabled, the center prompt enters `Tasker`, while the bottom edge enters `Stick`.

## Barrage And Fullscreen Alerts

These are separate rules and must not be treated as a two-choice switch:

- Island visibility rule: decides whether the normal island window is shown, hidden, or taskbar-following.
- Barrage rule: decides whether barrage preview or barrage messages render across the screen.
- Plugin alert rule: decides whether plugin due notifications render as island, toast, or barrage while fullscreen or maximized content is detected.

Current implementation:

- `FullscreenPluginAlertOverlay` renders plugin alert card styles.
- `BarrageOverlay` renders barrage preview and fullscreen barrage messages independently.
- Tasker fullscreen detection uses `last_scene_probe_reason` even when `scene_suppressed` is forced false for a visible taskbar island.
- Settings barrage preview syncs only the barrage overlay, not the plugin alert overlay.

## Music And Lyrics

- Real media state comes from `WindowsMediaProvider`.
- No active media session should show an empty or diagnostic state, not fake sample tracks.
- Local and online lyric files live in `lyrics/`; this folder is the active lyric library for desktop testing.
- The generated lyric cache is bounded by age and file count when a separate generated cache root is configured by tests or future packaging.
- `TrackData` remains the shared media contract.
- `TimedLyricLine` carries optional `TimedLyricUnit` start/end timestamps and a timing-source label. Keep those fields through provider handoff and generated-cache reloads; do not infer a sustained syllable from a missing end timestamp.
- NetEase, BetterNCM, QQ, Qishui, and Kugou integration paths are optional app-profile attachments. Only configured app paths should be listened to.
- Generic Windows media remains the baseline provider route.

Downloaded artwork uses `%LOCALAPPDATA%/GluSpot/cache/album_art` (or `GLUSPOT_ALBUM_ART_CACHE_DIR`), keyed by the full image URL. Generated online lyrics use `%LOCALAPPDATA%/GluSpot/lyrics-cache` by default. The settings cleanup removes only owned, direct cache files; it does not recurse or follow redirected directories or file links. Legacy online-source markers are recognized in the separate generated directory. When a configured generated directory shares the manual library, only files carrying `[re:GluSpot generated cache v1]` are disposable; unmarked imports are preserved. Source statistics and the established title/artist/preference lyric cache identity remain unchanged. A GUI media read uses the immutable snapshot's time projection while cleanup owns the cache lock; it does not wait for disk deletion or launch another refresh during that interval.

## Audio Output Devices And HomePod

The full-screen/windowed music pages include an output-link chooser. It lists active Windows speakers and already connected Bluetooth outputs, confirms console/multimedia default changes, and discovers HomePod on the local IPv4 network. The chooser's Ctrl+N shortcut opens a temporary manual-IP dialog when discovery is unavailable; the compact panel has no redundant heading, permanent IP field or **更多选项** section. F5 refreshes devices; capture scope remains in tooltips and accessibility descriptions. Newly available local devices show a brief connection animation. Bluetooth pairing stays in Windows; players with a fixed/exclusive output may need their own output changed. Device enumeration does not open a microphone or loopback stream.

Single HomePod casting uses an independent native WASAPI capture → bounded PCM ring → AirPlay 2 sender. The current single-receiver mode forwards all computer application playback, including notifications and apps pinned to other outputs. Exclusive casting prefers Windows process loopback excluding the helper's own process tree; this API requires Windows build 20348 or later, with actual activation deciding availability. If unavailable, capture falls back to the selected output's system mix. No microphone or virtual output driver is used. After HomePod authenticates, the selected local output is muted before capture starts; stop/error/exit restores its original mute state without changing volume. The parent restores owned mute after an abnormal helper termination; an explicit external unmute ends the cast. Apps pinned to another output can still sound on that output because only the selected endpoint is suppressed. The chooser uses selectable device rows without visible checkboxes: selected rows have a volume-filled capsule or a gray capsule when volume is unavailable; unselected rows show their icon/name. One selected AirPlay receiver uses this computer-wide path; selecting two or more outputs starts coordinated capture of only the current music application, including all-Windows/Bluetooth groups. The eight-output limit now includes any selected Windows endpoints, so wired speakers and Bluetooth can remain checked together. The source endpoint must be separate from every playback endpoint; automatic application routing uses an available unoccupied output, and failure never broadens capture or silently replaces a member. It displays the scope during connection and playback. Reducing a group to one receiver stops the shared renderer, restores the music application’s owned route, then starts computer-wide casting; a default/capture endpoint is never an implicit checked group member. Changing the selected source endpoint or exiting stops the helper; selecting a receiver explicitly starts a cast.

Connection, authenticated waiting, flowing audio and errors are reported separately. Entering flowing audio requires recent accepted nonzero capture samples and nonzero PCM handed to the UDP transport. Signal diagnostics retain only counts, last-signal age and peak, never captured content. Fresh evidence of at least three seconds without source signal shows “已连接 HomePod，暂未检测到电脑声音”; resumed signal clears that message without reconnecting, seeking or changing volume. Stale/previous-session samples cannot renew signal status. These checks distinguish zero PCM from flowing signal, but do not prove that a HomePod speaker is audible. The current Realtek endpoint was physically reproduced returning zero PCM after mute, while process loopback retained nonzero PCM under the same mute. A separate 90.032-second HomePod mini cast passed and the user confirmed normal sound with only HomePod audible; the previous M6 pass remains separate evidence.

Casting now keeps display compensation fully automatic. It starts from the existing 1.5-second protocol buffer and gradually follows clean sender-buffer evidence; older stored manual delay/automation values are ignored and cannot disable the automatic path. There is no manual delay slider or automation switch in the chooser. A shared display clock follows batched estimates continuously instead of shifting the word front on each arrival. Small negative player-clock corrections keep the reading front moving at a bounded rate; pause and verified Seek behavior stay separate. Compensation does not alter player progress or lyric Seek commands and is not a measurement of HomePod's acoustic output.

Each device row can show its confirmed volume and an inline slider. Windows outputs use native endpoint volume with readback. The active authenticated HomePod exposes volume only after receiver information, a volume read, or an acknowledged command supplies evidence; an unknown volume remains unavailable. Dragging a slider does not select another device, change the capture source, or release local mute ownership. Receiver failures are reported without tearing down a healthy cast. The compact chooser uses the music page's font and a cached half-size blurred crop of the music page’s already displayed background with a neutral veil; it reuses the background raster instead of repainting the lyrics and refreshes at most once per second; device icons preserve the supplied SVG proportions and alpha. Native Qt fixture rendering and automated protocol tests cover these behaviors. HomePod volume control has not yet been checked on physical hardware in 6.405, and multi-song audible lyric alignment still needs listening QA.

The Apache-2.0 sender is pinned with provenance and notices; restricted AirSonic/AirFlash code is not incorporated. `python-zeroconf` remains an unmodified, replaceable LGPL discovery dependency with source and notices included in the Windows package. `build-exe.bat` builds/tests the native helper before packaging; CMake and a Windows C++20 toolchain are now required for test builds. See [audio routing behavior and evidence](docs/audio-routing.md) and [native helper build instructions](native/airplay_sender/README.md). The repeatable 30-second disconnect came from missing transient-authentication event keys: encrypted HomePod requests were discarded instead of acknowledged. On October 1, the fixed controller cast from Bluetooth M6 to HomePod mini “起居室” for 90.06 seconds without interruption, muted/restored M6 and acknowledged real encrypted events. The user confirmed only HomePod was audible and delay was acceptable. The existing 1.5-second RTP timeline setting is retained; this is not a measured universal latency floor. Multi-hour playback, other drivers/firmware and sleep/reconnect still need hardware verification before release.

Both CAA paths use a trusted 1200 variant of the verified front or its documented `front-1200` endpoint, keeping unlimited original files from repeatedly exceeding the 8 MiB download budget. MusicBrainz/CAA still require a known matching duration and, without an album name, one unambiguous group. Lookups stay off the UI thread with track-bound generations, bounded workers/caches, source cooldown and a delivery deadline; original bytes retain NetEase/CAA provenance through loading-ripple completion. MusicBrainz requests share a process-wide one-request-per-second gate and an identifying GluSpot User-Agent. Unknown duration or releases spanning different groups return no MusicBrainz/CAA match. Source-limited originals complete acquisition even on larger/high-DPI layouts; that does not claim that the source provides native pixels for every display. This is for the internal non-commercial test build: the [MusicBrainz API policy](https://musicbrainz.org/doc/MusicBrainz_API) and [CAA API](https://musicbrainz.org/doc/Cover_Art_Archive/API) do not remove the release's content-rights review. [LDDC](https://github.com/chenmozhijin/LDDC) aggregates several platforms rather than being a separate lyric database; no LDDC runtime or new credential-based service was added.
- Proposed background direction remains unimplemented: preserve album colors, use slow breathing movement in quiet passages, and gently push the side glows on sustained drum activity with about two seconds of transition between strengths. Reuse the optional output loopback analysis; do not infer semantic chorus labels or alter playback devices. Keep the lyric area stable, cap brightness, and return to quiet motion on pause or missing analysis.
