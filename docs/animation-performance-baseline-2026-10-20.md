# 6.415 动画性能基线与测量边界

日期：2026-10-20。原版源码：`a1c0a5f1ddaee5de5ce243ec00dd3e68ab3e20b7`（`v6.415`）。本文件记录优化前证据；后续源码性能结果应单列，不覆盖基线。当前不据此宣称桌面实际帧率，也不涉及打包或发布。

## 方法

新增 `tests/perf_music_surface.py`。同机、串行，每个配置独立进程／QApplication，不启用 profiler；`long-song` 为现有 benchmark 的 180 行长歌词，`unit-slow` 为 24 行具有真实逐字时间、首词长音的歌词。尺寸为逻辑像素 960×540、1920×1080，DPR 1／2；DPR 2 的 QImage 两轴均按物理像素扩展并设置 `devicePixelRatio`，窗口的 DPR accessor 同步。

每格单独记录构造、第一帧；随后 60 冷阶段帧、120 预热帧、300 稳态帧。每帧推进 8 ms 模拟播放时钟，调用真实 animation tick，合并该 tick 实际请求的脏区，再向 QImage 渲染。tick、区域合并、render 和合计独立计时；每格稳态均得到 60 次全幅／240 次局部绘制。控件保持显示，避免与五秒自动隐藏混测。保留每一帧原始数据、P50／95／99／max，以及 >8.33／>16.67 ms 数量。

环境：Windows 11 build 26200，AMD Ryzen 5 7535H（6 核／12 线程），CPython 3.12.10，PySide6／Qt 6.12.0，Qt Windows platform。每格独立进程隔离 Qt／字体／应用缓存，但系统字体及磁盘缓存仍可受前序进程影响，因此“冷”表示进程内首次使用，不等于重启系统后的冷启动。

这测量 Qt／Python 栅格工作负载，**不测 DWM 呈现、物理显示器 FPS 或真实 QTimer 调度延迟**。8 ms 是输入时钟步长，不表示机器已经实现 125 FPS。SyntheticOwner 无音频、网络或真实后台平台请求，原版 `_run_background` 回调同步运行；真实生产预处理的异步等待须在后测另列。QImage 输出也不代表物理桌面交互体验。已打开检查 long-song 960×540 DPR 1 与 unit-slow 1920×1080 DPR 2 输出，确认均绘制实际歌词和预期高光内容；这只确认静态帧内容。

## 独立诊断与热点

另行执行有 inclusive method wrappers 的 8 格诊断（60 冷＋120 预热＋60 稳态），并单独对 long-song 1920×1080 DPR 2 执行 cProfile。这些有插桩样本**不混入上述正式指标**。方法耗时包含其内部调用，不能相加当作整帧分解。

该配置的诊断中，`_resolve_display_lyrics` 单次最大 82.57 ms，P95 为 0.082 ms，显示首次清理／映射与稳态是不同问题。`_advance_song_layout_build` P95 3.42 ms；`_paint_background` P95 8.82 ms；`_paint_control_layer` P95 14.88 ms、max 21.32 ms；一次 transition snapshot 为 42.06 ms。

单独 profile 中 301 次 paint 累计 8.04 s，主要可见成本为 `QPainter.drawImage` 2.06 s、`_paint_control_layer` 1.24 s、`_paint_background` 1.06 s、`paint_liquid_glass` 1.01 s、`_paint_lifted_run` 0.84 s；布局模式判定也频繁出现。上述累计值含嵌套且受 profiler 影响，用于定位，不用于承诺优化幅度。

审计后为 glyph run、完成的 isolated units 和 partial builds 增加条目／字节口径；tint／halo 同时有条目和字节上限。当前发光行、单个 last run／partial build 属于明确的工作集：任意长正文不能既保证完整效果又承诺绝对固定像素量，因此报告固定 cold 预算及实测 current／working bytes，不声称所有缓存总和永远小于固定阈值。`_glyph_cache` 通常是 run cache 的 QImage 别名，不能重复算作独立像素。

`tests/test_music_glyph_cache_resources.py` 逐项用真实 `sizeInBytes()` 重算计数，覆盖 partial→complete 转移、当前行受未来预热挤压、旧颜色释放、换色后的 readiness，以及命中完成行后旧 partial 失去 working 例外的收敛。最后一项曾复现 52,576 bytes 旧 partial 超过 4,096 bytes cold 预算，生产已修正命中分支的 trim，6 项再次通过。此处是小预算压力回归，不是长期进程内存保证。

`tools/benchmark_glyph_cache_eviction.py` 在独立进程分别量 OrderedDict bookkeeping、QImage wrapper 最后引用释放和 bulk clear，明确区分共享像素、独立像素及外部 owner。原始数据保留在 `.runtime/animation-followup-2026-10-20/glyph-cache-eviction-production-reference.json`，不使用 profiler，也不进入正式帧矩阵。

## 原生可见窗口的后台材质测量口径

下一轮 QImage 正式矩阵保留默认同步像素路径，用于可比的 raster 工作量；它不能证明 live QWidget 后台材质／背景的收益。实际窗口另外使用真实 QTimer 和真实墙钟，在采样期间不导出 PNG、不 `grab()`，分别记录事件循环 tick／paint duration、调度间隔和资源。即使无 profiler，paint 入口计时仍只是 Python／Qt 工作量及观察器开销，不能当作 DWM 呈现 FPS 或物理屏幕 60 Hz。

独立材质诊断按 serial 关联 GUI request、pending→submit、MusicTasks worker 进入／退出、Qt GUI delivery、accepted 与随后 paint，分开报告排队、纯像素 render、信号交付和首帧交接。`prepare_seconds` 只有最近一次纯 render，不能替代端到端时间。记录 active、pending、input/cache bytes、hits/misses、discard/reject，以及隐藏／恢复和关闭后的线程退出；截图、动画 correctness observer、正式 paint 及 profiler 分开运行。`tools/verify_animation_lifecycle.py` 的可见动画检查保留为 correctness／诊断，不作为正式 FPS。

背景计算仅增加可选 live-owner 路径，首个完整帧与明确截图仍同步；后续不可变数值 snapshot 复用同一个有界 GlassPixelTasks worker／队列，不带 QWidget、字体布局或可变 renderer。accepted 前保留旧 frame，接受后才更新实际 `_painted_colors`／strengths 与 contrast 身份。新测试已覆盖与同步逐字节像素相等、旧 palette／同 raster 不同 logical size 的拒绝、同步截图 fencing，以及真实 worker 离开 GUI、GUI 交付和歌曲变化后旧结果丢弃；现有 25 项背景颜色／运动／缓存回归和 6 项新测试通过。随后冻结源码完成下节正式复测；原生交接与长期资源仍须按独立 live 测量范围判断，本段本身不作性能验收结论。
