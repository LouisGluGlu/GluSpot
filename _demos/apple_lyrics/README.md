# 仿 Apple 歌词示例

这是一个能单独打开的对照窗口，不是正式播放页。不改产品歌词、按钮、玻璃和播放模式，不写设置，不启动网易云，也不连接调试端口。

句子是为了演示写的，不是某张专辑里的歌。深色背景用仓库里已有的封面照片，走产品现成的封面取色（`artwork_surface_palette` + `flow`）。白底就是白纸，字改成深色。

## 怎么打开

Windows，在仓库根目录用已经配好的环境：

```bat
_demos\apple_lyrics\仿Apple歌词.bat
```

← → 切换「现在的歌词」和「仿 Apple」。B 切换深色 / 白底。1–4 换封面。空格暂停。Esc 退出。右边滑块只改仿 Apple，不写入设置。

三个跳转按钮：

- 看长音：停在「慢」上，能看到这个字慢慢被擦过去。
- 看提前换行：新的一句已经变大变清晰，但它还没开唱；上一句的「慢」还在擦。
- 看长间隔：上一句已经唱完，画面先不动，离下一句开唱还早就不会滚。

## 仿 Apple 在做什么

- 左对齐。主句粗体，译文更小、更细，贴在主句下面。默认译文间距是主字号的 0.25 倍，句和句之间是主字号的 1.75 倍。
- 正在强调的那一句是 100% 大小、不糊。其他句默认缩到 88%，离得越远越糊、越淡。相邻大约 25% 亮度，更远大约 10%。
- 深色背景上，已经擦过的字是白 100%，还没擦到的字大约白 55%。译文大约 45%，而且不跟着逐字擦。白底时同样的比例，只是换成深色字。
- 逐字擦除按每个字自己的起止时间匀速往前走。拖长的「慢」会慢慢爬过这一个字，擦完就停在 100%，不再闪、不再上浮、不再单独缩放。前沿有大约 0.75 个字宽的软边。
- 没有逐字时间的那一句（「桥下的灯一盏盏亮」）把整句时长平均分给每个字，当作兜底。
- 提前换行：滚动开始时间 = 下一句第一个字的开始时间 − 提前量。默认提前 350 毫秒，滚动本身也是 350 毫秒。整页一起挪，后面的句子不会一个个晚半拍。
- 强调（变大、变清楚）跟着这次滚动提前换到下一句。擦除不提前，仍然只看音频时间。所以新句可以先以大约 50% 的亮度到位，到它开唱才开始擦。旧句在上移、缩小、变糊的同时，把剩下的字擦完。
- 两句之间隔得很久时，也只提前这 350 毫秒，不会在当前句一唱完就滚走。

这套示例曲里可以核对的时间：

- 3.45 秒开始滚向第二句。这时上一句的「慢」擦到大约 53%（落在观察里的 50%–75%）。
- 第二句 6.45 秒唱完，第三句 9.70 秒才开唱。滚动要到 9.35 秒才开始。7.20 秒的截图还停在第二句，并写着还要再等。

「现在的歌词」是对照，不是把正式绘制原样搬过来。它用的是现在播放页上的这些数：主句和别的句子一样大；句距大约是 `max(18, 窗口高×0.035)`；译文大约是主字号的 16/38，而且译文也逐字擦；别的句子按距离模糊 0 / 3 / 6 像素；未唱到的字大约 95% 白，不是仿 Apple 那种淡到 10%。已经擦过的字会轻轻上浮大约 5 像素，羽化大约两个字宽。滚动要等这句真的开唱才开始，不提前。正式产品里后面的句子还会稍晚跟上，这个示例两边都是整页一起滚，所以不要拿它去验收那个错开。

## 接入正式播放页时要哪些数据

示例没有改正式绘制。真要接进去，时钟要分成两路，不要共用一个提前量：

1. 滚动看下一句第一个字的开始时间，再减去提前量。有逐字时用这句第一个 `TimedLyricUnit.start_seconds`；只有整行时间时用 `TimedLyricLine.time_seconds`。不要用「当前句结束」当滚动点。
2. 擦除只看每个字自己的 `start_seconds` / `end_seconds`，在这一段时间里匀速走过这个字的宽度。不要把那 350 毫秒再加到擦除上。
3. `end_seconds` 为空时，现有模型写明了：可以拿来估一个显示进度，但不能把它当成这个音被拖长的证据。
4. 一句完全没有逐字时，`timing_kind` 是 `line`。只能把这一行的时长平均分给每个字，并且标成估算，不能假装是采到的逐字。

仓库里已经有的来源：

| 数据 | 现在到哪一步 |
| --- | --- |
| 网易云 YRC | `api/lyrics.py` 能解析每个字的起点和时长。播放入口已经接了 YRC。 |
| AMLL 的 TTML | `api/ttml.py` 能读 span 的 begin/end 或 dur。整句的字都能对上原文时，才标成 `unit`。这是 AMLL 的歌词文档，不是 Apple 官方接口。 |
| QQ 的 QRC、酷狗的 KRC | 解析函数在 `api/lyrics.py`。播放入口的说明仍写着这两家的逐字还没接到线上播放。 |
| Apple Music 官方接口 | 仓库里的平台说明写的是：公开接口没有逐字歌词。 |
| 只有一行一个时间的 LRC | 已有，对应 `timing_kind == "line"`，只能走上面的平均分配。 |

另外，正式播放页现在就有一个行号提前：网易云网页进度那路大约 0.28 秒，多数来源是 0。那是为了补偿进度报送，用来选「现在唱到哪一句」，不是这版 350 毫秒的视觉滚动，也没有把「句子提前变大」和「字仍按音频擦」拆开。

## 离屏检查

```bash
QT_QPA_PLATFORM=offscreen PYTHONDONTWRITEBYTECODE=1 python3 _demos/apple_lyrics/check_demo.py
QT_QPA_PLATFORM=offscreen PYTHONDONTWRITEBYTECODE=1 python3 _demos/apple_lyrics/grab.py
```

检查提前量、长间隔、长音的左右亮度、没有逐字时的平均分配，以及深色背景确实暗、白底确实白。离屏耗时不代表 Windows 上的顺滑程度。
## Named parameter presets

The current knobs remain the default. Run `demo.py --preset soft_close` for
closer, clearer neighboring lines, or `demo.py --preset dramatic` for more blur
and separation. Existing sliders reflect the preset; reset restores today's
knobs. [Exact numbers and offscreen comparison sheets](../par_decisions/README.md).
