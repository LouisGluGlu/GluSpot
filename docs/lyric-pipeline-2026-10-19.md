# 歌词处理：署名、间奏与来源扩展（2026-10-19）

本次只修改源码和验证，版本保持 **6.412**，没有重打安装包、便携包或 EXE。沿用现有 provider、歌词模型、播放时钟、请求代次与缓存入口；不增加播放控件，不调整页面布局。

后续用户已授权打包；现代 Windows x64 产物、打包复核发现的 QQ SDK 回退修正，以及新的 5443 项完整回归记录在[歌词版发布报告](windows-release-lyrics-2026-10-19.md)。本页保留前述源码阶段的独立验证记录。

## 第一阶段：署名识别

`local/music_lyric_presentation.py` 以明确制作字段建立证据，再识别开头连续的署名块。补齐长双语字段、指挥／乐队、组合职位、分隔符和有证据支持的相邻未知职位；单条明确署名仍可清理。冒号、短句和停留时间本身都不是删除依据。

回归覆盖 `作词 Lyricist`、`作曲 Composer`、`斯瓦希里语顾问 Swahili Language Consultant`、罕见乐器与连续未知职位，同时保留“鼓起勇气：向前走”“他说：我爱你”、已验证的歌手标签、对唱分工、原译文、罗马音和括号和声。沿用现有网易云结构化头识别，只清理符合其实际 schema 的元信息；普通花括号正文和无关 JSON 不被泛化删除，旧时间戳包裹的元信息不再成为合成歌词。

岛态移除按关键词截断正文的旧路径，改用共用清理结果并保留原始索引。清理后没有有效歌词时使用现有“暂无歌词”，不把该状态当作纯音乐。原始内容与持久缓存不写入展示过滤结果。

本阶段集成验证：**191 项通过**。日志：`logs/lyric-stage1-2026-10-19.log`。后续补充的占位状态、歌手时间映射等边界纳入最终完整测试。

## 第二阶段：前奏与间奏

新增 `local/music_lyric_intervals.py`，在最终保留的展示时间轴上计算空档，复用现有 `· · ·` 提示和圆点绘制。前奏阈值保持 **5 秒**；中途空档必须**严格超过 3 秒**，且前面所有可能仍在发声的保留行都有可靠真实逐字结束时间。毫秒时间相减产生的浮点误差不会把正好 3 秒变成间奏。

重叠主唱、同时间对唱和仍在延续的括号和声共同决定最晚结束时间。普通 LRC、合成时间、缺失结束时间和无法对齐原文的逐字行不推测中途间奏。遇到无法证明结束的保留人声后，首版保守地停止推断后续间奏；这可能漏掉一些真实空档，但避免长音／和声误判。没有新增估算尾奏。

窗口、全屏、封面内外歌词和岛态复用同一判定。移除主绘制和模糊预热路径中“只有第 0 行是前奏”的限制。圆点直接读取已校验的实际播放位置及歌词偏移：暂停不推进，快进／回退重新计算，下一句在原始开始时间接管。歌词重载、翻译开关和过滤结果变化会重建展示段，重复计算不会重复插入；切歌沿用身份和代次校验。

## 第三阶段：QQ QRC 与 AMLL

QQ 从“能解析 QRC”扩展到实际获取链：验证公开歌曲详情中的 MID／数字 ID，使用现有固定版本 SDK 的 HTTP 客户端请求 `PlayLyricInfo.GetPlayLyricInfo`，取得加密 QRC／译文／罗马音。`api/qrc.py` 独立实现其协议解码，使用 Python 标准库，无新增运行时依赖；标准 DES 用 FIPS 向量验证，QQ 变体用真实公开响应交叉核对。损坏或不可用的 QRC 回退既有 LRC；请求、密文与解压体积均有上限。

`api/ttml.py` 用标准库解析有界 AMLL TTML，保留原 XML、真实单位时间、译文、罗马音、agent 和背景人声信息。不凭段落结束时间合成逐字单位，拒绝 DTD／实体和不支持的时钟形式。TTML 的文档／最后人声结束时间不等于歌曲时长。

AMLL 仅凭可信网易云／QQ 歌曲 ID 查询，并要求结果回显该 ID、标题／歌手／版本兼容。若有明确录音时长则核对，歌词时间轴不能超出已知歌曲时长的容差。保留手工本地歌词优先权与现有网易云 YRC／LRC、QQ、LRCLIB 路径；AMLL 是有限回退序列中的末项，真实逐字时间才可升级行级／合成时间。

程序内播放先展示已取得的官方歌词，再复用有界低优先级 worker 查询一次可信 ID 备用源。已有真实逐字歌词无需继续搜索。超时、限流、未命中、无效格式、队列拒绝和不兼容候选都不会清空当前歌词。官方接口失败仍可进入同 ID 回退；取消／关闭不复活。歌曲、完整版本／时长、catalog、播放 epoch 和歌词偏好代次共同阻止旧结果覆盖新目标。

跨源补译文／罗马音必须重新验证至少 80% 原文有序匹配及匹配行开始时间差不超过 0.75 秒，不直接拼接其他版本的内容。原始网易云所有歌词变体、解码 QRC、TTML 与来源记录随现有生成缓存保存，过滤文字和间奏标记不持久化。兼容附属来源使用有界单层记录，重新解析时重验原文和时间轴；翻译开关不会销毁休眠的原文／译文／罗马音。AMLL 可信 ID 查询的内存正缓存为 1 小时、负缓存为 60 秒，条目数量有界，清缓存的代次使旧网络请求失效；既有生成文件的持久缓存规则保持原样。

本阶段来源／解析／缓存／服务回归 **215 项通过（3.743 秒）**，程序内歌词升级／偏好／播放回归 **102 项通过（2.430 秒）**。日志分别为 `logs/lyric-stage3-sources-final-2026-10-19.log`、`logs/lyric-stage3-owned-final-2026-10-19.log`。Node bridge 语法检查通过；原生桥契约随来源测试验证。

## 参考、依赖和发行条件

按用户指定的 Folia 提交 [62c35156b01e165201dc999e0961f2e0e6dff68c](https://github.com/chthollyphile/folia-major/tree/62c35156b01e165201dc999e0961f2e0e6dff68c) 核对署名块、解析、QQ 与 AMLL 的实现思路。Folia 为 **AGPL-3.0**；本次未复制其实现、未引入该项目或新增加密／TTML 运行时依赖。通用 DES 依据 FIPS PUB 46-3，QQ 协议事实经公开响应核对。
