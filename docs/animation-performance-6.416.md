## 第一阶段：歌词展示准备

新增 `local/music_lyric_preparation.py` 与 `music_lyric_preparation_store.py`。清理、同时间合并、括号和声附属、可靠间奏、逐行时序和显示层拆分生成 immutable 结果。真实 island owner 在歌词／设置变化时提交；窗口、全屏、专辑内外和岛消费一致计划。岛仍保留原始索引投影，不被展示间奏改变播放索引。时间轴完全相同时共享 immutable row plans；有过滤、和声结束或间奏插入时独立映射。

worker 仅接收字符串、数值、tuple 和 frozen dataclass。Qt 字体、QTextLayout、QPixmap、QWidget、信号交付与缓存接纳保留在 GUI。使用现有 `MusicTasks(worker_count=1)`；一个在途、一个可替换 pending。接纳时重查实际歌曲身份、内容版本和代次。译文／罗马音／对唱、真实和估算时间的语义不变。展示处理不写回原歌词或持久缓存。

同一歌曲兼容结果继续显示；新歌不借用旧索引。缓存至多 4 条／8 MiB，单个超大当前结果仍可显示，但不保留多个超大缓存。纯准备总量、GUI 快照和 submit→ready 分开测量，不能用后台等待前的 loading 充当更快首帧。

## 第二阶段：材质、图层和资源

- 背景按颜色／权重值复用分析；保留原 256 像素有界场与 30Hz 几何／取色过渡，不增加完整 DPR 背景副本。
- `local/liquid_glass_tasks.py` 复用现有 `MusicTasks`：一个像素 worker，最多 16 pending、64 roles／弱 owner、输入 16 MiB、ready 4 MiB；既有同步材质缓存另限 4 MiB。注册采用 LRU，过期歌曲、几何及设置结果丢弃，隐藏／最小化／销毁失效，退出关闭。没有新高频 timer。
- live 玻璃、设备面板刷新及背景数值快照进入同一队列。纯像素代码只使用独立 QImage wrapper、NumPy/Pillow 和 QImage 上的 QPainter；不操作 QWidget／字体／QPixmap。Qt QImage reentrant 不代表可共享可变 wrapper。输入 wrapper 隐式共享与真正深拷贝分开计量。
- 未就绪时保留兼容旧材质；首次玻璃使用已有 veil／rim 等待。缺失背景、设备面板首次及显式 `render/grab` 保持同步完整。`GlassCaptureMixin` 和显式 capture scope 处理 Qt 重定向：不能凭 `painter.device()` 判断截图，因为实际观察到 redirected paint 仍返回 QWidget。
- 接纳背景只在全幅 damage 交接，不在歌词局部刷新中撕裂背景。实际 accepted 的颜色／强度决定中断后的过渡起点；对比度沿用同一缓存身份。
- 光学 raster 与 hover／pressed／主题 veil 分离；控件几何移动复用材质，悬浮和图标继续实时绘制。宽窄布局只缓存当前尺寸／字体／DPR／DPI 的测量。
- glyph run 128 条／16 MiB；isolated glyph 128 条／24 MiB；partial build 16 条／8 MiB；tint 2048 条／16 MiB；halo 1024 条／24 MiB。冷资源受限，当前可见行与单个 last run／build 作为工作集保护。异常超长当前歌词可超过固定冷缓存预算，不能宣称整个进程内存绝对固定。字段中的 QImage alias 不重复计算像素。

保留两项负结果：完整 DPR 背景副本和 fully-visible 控件光栅缓存均因 P95 回归撤回；原直接绘制和退出 blur 层保留。持续背景不能阻断原控件预热，每次依旧按原单层／35ms 预算执行。

真实生产缓存 48 次退出层淘汰 P95 0.0073ms；饱和 64 MiB 像素淘汰 P95／max 0.1959ms，最后持有者整批释放 2.2117ms。另有共享 wrapper 非最后持有者释放仅 0.019ms 的对照。因此未为假设热点新增退休队列。空闲 `MusicTasks` 可共享保留最后一张结果，cache_bytes 不等于所有像素或 RSS；关闭 worker 后释放。完整数据与方法见[基线文档](animation-performance-baseline-2026-10-20.md)。

## 第三阶段：刷新和连续页面导航

收藏／喜欢栏仅在其实际可见矩形与 damage 相交时绘制材质，包含边缘外扩；命中区域与交互保留。原背景、歌词、封面、控件的脏区机制继续覆盖前后位置、模糊与 AA，不重写整套算法。

登录、音乐库和播放共用已有 `MusicNavigationTransition` 实例。`request_start` 先保持／绘制有效来源，随后在 Qt 线程准备最新目标。等待期间旧过渡继续或停在有效末帧，目标准备后交接。截图时恢复原 enabled 样式，避免拍到临时 disabled 按钮；用户输入在过渡阶段仍受原规则保护。

快速反向从当前已合成图层、独立封面位姿、圆角、角度和解析速度开始，保留原 260／560ms 时长；中断轨迹使用 Hermite，普通未中断动画保持原曲线。连续请求、隐藏、取消、目标销毁均释放快照与 freeze ownership。目标重拍仅释放该页面旧 freeze，来源时钟保持冻结到交接结束。

来源先绘制只是 raster 顺序保证，不是呈现 fence；目标 QWidget 抓图仍是同步 GUI 成本，未宣称所有点击长帧已消除。缩小抓图虽有耗时收益却改变文字 AA，未采用。

## 第四阶段：时钟与生命周期

普通播放请求从 8ms 收敛至 16ms，沿用基于显示刷新率和实测 tick／paint 成本的高刷分支。16ms 不是实际 FPS；不降低动画时长，不改变媒体真实时钟。已有逐 tick 排版、字形和 blur 预热优先级保留，不叠加新 timer。

音乐库被过渡图层覆盖时冻结背景、旋转封面和骨架时钟；骨架枚举既有 row／shelf，不重复遍历 QObject 树。隐藏／最小化暂停 surface 绘制时钟与后台接纳；恢复后继续；播放时钟不受影响。没有加入跨所有任务的硬截止调度器，不能把现有分批预热称为统一硬预算。

## 最终验证与性能结果

冻结源码后的完整回归为 **5,691 项／405.130 秒，全部通过**，117 个应用源码哈希与冻结记录一致。早期全量运行仅一项同步材质假设失效，测试已改为核对真实后台完成前后且不重绘歌词；修正后完整重跑通过。相邻 old/new 八格离屏矩阵与独立热点诊断均已完成。历史候选及失败记录保留在[基线文档](animation-performance-baseline-2026-10-20.md)。

同条件离屏稳态 7／8 格 P95 降低约 **3.02%–6.94%**，长歌 1920×1080 DPR 2 为 **70.89→71.06ms**，轻微回归。八格 P99 均下降，但两格最大值和长歌 960×540 DPR 1 的超 16.67ms 数量回归；冷阶段五格最大值回归，包括长歌高 DPI **113.55→140.35ms**。重场景尚未稳定满足 60Hz，不以数个百分点的单轮变化作保证。

第一阶段减少的是 GUI 绘制栈中的同步准备，未使纯 CPU 算法整体变快：无缓存准备的四种样例 P50／P95 均增加，长歌 P95 **134.81→149.79ms**；GUI 不可变快照 P95 不超过 **0.109ms**。首 paint 已等待完整计划，不能把它的下降当作整体启动更快。第二阶段撤回了两项 P95 回归的缓存试验；保留的后台像素路径另用可见窗口采样，离屏同步玻璃不能替代其证据。第三阶段仍有 GUI 目标截图成本，第四阶段未新增覆盖所有任务的硬帧截止调度器。各阶段的量化数据和负结果均列在基线与可见回调报告。

新共享歌词 store 在长歌／逐字样例保留约 1.21／0.15 MiB；离屏稳态 Private 差约 −1.48 至 +4.34 MiB。字形像素按相同容器口径重算，不能将旧版缺少计数字段视作零占用。短场景关闭后 Music worker 回到零；这不是长期无泄漏证明。

离屏测量使用相同设备、分辨率、DPR、样例和计时方式，各格独立进程，不含 profiler；等待完整歌词和真实锚点再测 paint。可见窗口另用 `tools/benchmark_animation_event_loop.py`，采样期间不截图，分别记录 paint／timer callback 与间隔；八个正式与四个诊断进程已完成，数据、资源峰值及其回归见[可见回调报告](animation-visible-callbacks-2026-10-20.md)。这些仍不等于 DWM FPS。动画正确性与生产 PNG 检查见[原生验收](animation-lifecycle-verification-2026-10-20.md)。

无截图的可见 Qt 采样中，960×540、DPR 1／2、长歌／逐字四格稳定 paint P95 降低 **2.10%–12.94%**，但两个 DPR 1 中位数升高、长歌 tick P95 增加，四格回调间隔超 16.67ms 的比例均升高。后台 request→submit P95 **62.08–144.52ms**，纯像素 P95 **46.16–54.59ms**；任务数量有界并不等于材质延迟已满足帧预算。没有据较短 GUI delivery 掩盖这些等待。

最终原生 DPR 1／2 各 165 项检查、53 阶段、47 PNG 全部通过。真实目标接纳时窗口／封面位姿连续，速度误差小于 `1e-5`；关闭后的任务与应用退出后的 worker 检查也通过。截图导出的早期测试干扰和修正过程单独保留，未为通过验证修改产品动画或降低条件。源码完整回归、独立静态复核和原生运行前后，117 个应用文件均与冻结记录一致。
