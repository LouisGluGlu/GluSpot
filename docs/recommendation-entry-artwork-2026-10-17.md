# 每日推荐与私人漫游封面 — 2026-10-17

GluSpot 6.412。此项对应用户截图中“为你精选”两张卡片只显示网易云标志的问题。

## 原因与修正

两张特殊入口的 `artwork_url` 在账号页面建立时一直为空；音乐库的缩略图队列只处理
非空地址，所以这不是图片下载后无法解码，而是从未发出实际图片请求。此前为避免
只为装饰而消耗私人 FM 的推荐批次，删除了旧的歌曲封面请求，却没有提供保留批次的替代路径。

现在通过既有、已验证的 `daily_recommendations`／`personal_fm` 歌曲接口取得首个真实可用
专辑图地址，并把这批歌曲保留在服务中。真正播放相同入口时一次性取走原批次。
封面与播放共享各自的工作线程锁；无论谁先开始，另一方复用同一结果，不额外跳过 FM 音乐。
没有引入猜测的首页接口或固定网络封面。

账号和普通歌单先显示，随后两个入口独立获取封面；单个失败不会关闭音乐库或覆盖
其它歌单的错误状态。封面元数据失败最多重试两次，下载、解码和缩略图仍沿用原有
双工作线程、有界重试、可见优先与预取队列。搜索期间只更新其后台歌单，不替换搜索结果。

## 生命周期与边界

- 缓存只含每日／FM 两类，每类最多一批预取歌曲；Node 响应仍受既有 8 MiB 上限约束。
- 封面元数据有效期五分钟；每日预取超时可刷新。未播放的 FM 批次保留到实际消费，
  避免仅因图片过期而丢弃已经推进的推荐批次。
- 登出、新登录、账号失效或服务退出清空缓存。入缓存和读取缓存均要求账号仍已验证，
  同时校验账号代数，防止并发请求在另一请求认证失效后重新写回旧歌。
- 来源切换会取消未开始的工作并丢弃迟到的元数据和图片，不能污染新来源。
- 服务确实没有提供任何图片时保留现有平台占位；不会虚构专辑图。
- 封面对应实际推荐批次的首个可用专辑图，并非声称平台提供专用的每日／FM 官方静态封面。

## 验证

`tests.test_online_music` 的 39 项离线测试通过（0.794 秒），日志为
`logs/oct17-recommendation-artwork-service.log`。回归覆盖两种并发先后、预取一次消费、
后续 FM 批次、每日有效期、无图片、失败恢复、退出重登与并发认证失效。

原生 Qt 控制器测试在 DPR 1／2 各通过 80 项（6.443／6.373 秒），日志为
`logs/oct17-recommendation-artwork-controller-dpr1.log` 和 `-dpr2.log`。

`tools/verify_library_recommendation_artwork.py` 使用生产服务、控制器、工作线程、HTTP
读取和 QImage 解码链路，在 DPR 1／2 各通过 16 项；实际卡片的中心像素与本地图片一致，
不止验证地址非空。涵盖先显示账号／普通歌单、FM 元数据单次网络失败恢复、图片 503
恢复、原批次播放复用、已消费引用释放，以及切换来源后的迟到图片／元数据隔离。
每个 DPR 导出等待、加载完成、来源隔离及两张封面近照，共十帧。已亲看最终加载图，
两张卡片均显示图片，文字和圆角正常。

证据与截图位于 `.runtime/recommendation-entry-artwork-2026-10-17/dpr-{1,2}/`，
成功日志为 `logs/oct17-recommendation-artwork-preview-dpr{1,2}-final.log`。
初次 fixture 使用随机本地端口，被生产图片校验的 80／443 端口限制拒绝，失败记录保留在
`logs/oct17-recommendation-artwork-preview-dpr1.log`。工具仅在其自身进程内放行本次
两个精确的 loopback URL；生产端口检查没有放宽，真实 HTTP 状态、字节预算和解码逻辑均未替换。
随后为 fixture 图片载入既有内嵌字体并重截，避免离屏字体回退生成方框；这也没有改动生产字体。

所有账户与图片均为明确标注的离线 fixture；未联系真实账户或控制用户正在运行的程序。
这些检查不证明真实账号的网络可用性，平台未返回封面时仍保留占位。
